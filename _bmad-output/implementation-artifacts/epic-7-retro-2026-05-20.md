## Significant Discovery: Deploy Script Silent Failure

### Root Cause

```bash
set -euo pipefail    # Exit on any error

pass=0
check_pass() { echo -e "  ✓ $1"; ((pass++)); }
#                                  ^^^^^^^^
# When pass=0, ((pass++)) evaluates to 0 (falsy) → exit code 1 → set -e kills the script
```

This is a well-known bash trap. `((expression))` returns exit code 1 when the expression evaluates to 0. The pre-increment value of `pass` (which starts at 0) is 0, so the first `check_pass` call always terminates the script.

### Impact

- `pre-deploy-check.sh` died after Check 1 (lockfile integrity) — Checks 2 (tests), 3 (build), 4 (migrations) never ran
- `test-pipeline.sh` died after Step 0a (oc login) — all 12 smoke test steps never ran
- `deploy.sh` called `pre-deploy-check.sh` and treated its exit as a failure, but since `set -e` was also in `deploy.sh`, the deploy steps were never reached
- **No Epic 7 code was deployed to OpenShift**
- **No smoke tests validated the deployed system since these scripts were introduced**

### Fix Applied

```bash
# Before (broken)
check_pass() { echo -e "  ✓ $1"; ((pass++)); }

# After (fixed)
check_pass() { echo -e "  ✓ $1"; pass=$((pass + 1)); }
```

`$((expr))` always returns exit code 0 regardless of the arithmetic result.

### Why It Went Unnoticed

The script appeared to work:
- Printed a green checkmark for the first check
- Exited cleanly (no error message, no red output)
- Returned to the shell prompt normally

Unless someone was specifically watching for "Check 2: Test Suite" to appear, the failure was invisible.

## Key Insights

1. **Tooling that silently fails is more dangerous than missing tooling.** The scripts existed, the agreements referenced them, and they appeared to work. The green checkmark on the first step created a false sense of security. Missing tooling gets noticed; broken tooling gets trusted.

2. **Per-story quality is high; systemic integration quality still has gaps.** Every story was code-reviewed, unit tested, and E2E validated. But the deploy-and-verify cycle — the system-level quality gate — was broken for an entire epic.

3. **Manual verification of script output matters.** A one-second glance at whether the summary line appeared would have caught this. We need the habit of checking for "Results: X passed, Y failed" at the end.

4. **Version and changelog are user-facing documentation.** They must be part of the release process, not an afterthought. The Help page is the only way users know what's changed.

5. **Review quality compounds.** The 7→7→4→0→0 patch trajectory shows that investing in foundation quality pays off within the same epic. Later stories benefit from earlier hardening.
