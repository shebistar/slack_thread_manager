## Challenges

1. **CRITICAL: Visual drift from mockup (the central finding)** — Story 9.2 extracted `BriefingPageFrame` as a shared header component and applied it uniformly across all three layout variants. The original mockup (`ux-design-directions.html`) intentionally showed DIFFERENT header styles for each direction: Direction 1 (News Feed) had a white header with red bottom border, Direction 2 (Dashboard) had a DARK gray-95 header with a vertical red accent, and Direction 6 (Split Panel) had a compact bar with a 2px red top accent. The unification erased this intentional differentiation. Once 9.2 set the pattern, every subsequent story (9.4, 9.5) replicated it. The drift compounded story over story.

2. **Navigation structure diverged from mockup** — The mockup showed a single integrated dark navigation bar (brand name + tabs + info in one row). The implementation uses two separate bars: a white AppHeader (brand name, role badge, logout) and a dark NavBar (nav links). This creates visual overhead and differs from the mockup's clean single-bar design.

3. **Featured card missing internal grid** — The mockup's Direction 1 featured card used a two-column internal grid (content left, related decisions right) with a red left border. The implementation wraps a standard BriefingCard in a div with a red left border — no internal two-column layout.

4. **"Consistency" misinterpreted as "uniformity"** — The epic's goal was "visual consistency." This was interpreted as "make all headers look the same" rather than "use the same design tokens and visual language while preserving role-appropriate layout differentiation." The mockup's intent was consistent *language*, not identical *appearance*.

5. **No visual validation against the mockup** — All 290 tests validated structure, accessibility, and behavior — but none validated visual fidelity against the original design mockup. The mockup was listed in story references but never used as an acceptance gate.

6. **Previous retro critical-path items still unresolved** — Deploy verification from Epic 7, version bump/changelog (A18), and ARCHITECT Keycloak user verification are now three epics overdue. QA-first reordering (A21) was partially honored at best.

## Key Insights

1. **"Visual consistency" and "visual uniformity" are different things.** The mockup intentionally differentiated layout headers for each role — Dashboard (dark, operational), Feed (light, scannable), Split Panel (compact, research-focused). Consistency means shared tokens and typography, not identical components. The team confused the two, and the result was visual regression despite technical improvement.

2. **The mockup must be an acceptance gate, not just a reference.** Every story in Epic 9 listed the mockup in its References section, but no story validated its output against the mockup's visual intent. Structural tests (does the h1 exist? does the badge render?) are necessary but not sufficient for UI stories. A23 addresses this.

3. **Design decisions compound across stories.** Story 9.2's decision to unify all headers into `BriefingPageFrame` set a pattern that Stories 9.4 and 9.5 replicated (Search and Help page frames). A wrong architectural decision early in an epic propagates to every subsequent story. Design decisions deserve the same scrutiny as architectural decisions.

4. **Foundation work was genuinely valuable.** The token system, semantic state tokens, accessibility landmarks, WCAG audit, focus rings, and test infrastructure are permanent improvements that carry forward. The visual drift is a corrective task, not a rebuild.

5. **Multi-model execution remains a validated strategy.** Five consecutive epics have now used multiple LLM models within the same epic. The BMAD story format serves as a reliable cross-model handoff contract.

## Significant Discovery: Visual Drift Requires Corrective Epic
