## Successes

1. **Clean two-track architecture** — Enrichment (8.1→8.2) and Backfill (8.3→8.4) delivered as parallel capability tracks within the same epic. Backend → Frontend pairing worked cleanly in both tracks.

2. **Review quality continued to compound** — Patch trajectory 8→6→3→0 mirrors Epic 7's 7→7→4→0→0 pattern. Story 8.4 achieved zero patches. Foundation quality from early stories propagates to later stories within the same epic, for the third consecutive epic.

3. **Source abstraction pattern (Promise.allSettled)** — Story 8.1's multi-source orchestration with per-source timeouts and partial-success semantics is architecturally elegant. Adding new enrichment sources requires only implementing the source interface — no orchestration changes.

4. **Multi-model execution success** — Opus 4.6 (8.1, 8.2, 8.3) and Codex 5.3 (8.4). Different model, different context window, zero-patch delivery. BMAD story format effective as cross-model handoff contract for the fourth consecutive epic.

5. **In-memory cache scope decision** — Story 8.1 spec suggested a persisted table, but the implementation chose a simple Map with UTC date keys. No migration needed, simpler code, appropriate for current scale. Good engineering judgment documented transparently.

6. **Ingestion neutrality maintained** — All four stories verified text-paste-imported data works identically to Slack API data. A2 agreement consistently honored.

7. **Zero production incidents** — Clean epic from a stability perspective, matching Epic 7.

8. **60+ new tests added** — Test suite grew from 675 to ~735+, covering enrichment service, source adapters, cache behavior, enrichment panel, backfill section, and briefing card historical badge.

## Challenges

1. **Keycloak ARCHITECT test user blocker persisted across ALL 4 stories (CRITICAL)** — Story 8.1 documented the gap ("No ARCHITECT/CONSULTANT users configured in Keycloak"). Stories 8.2, 8.3, and 8.4 each inherited and re-documented the same blocker. It was finally resolved post-epic by extending `test-pipeline.sh` with ARCHITECT user authentication (Step 12). The blocker was well-documented but never escalated to immediate action. **Documenting a blocker is not the same as resolving it.**

2. **Deferred items accumulation (18 items — epic high)** — Story 8.1 alone deferred 13 items. While many are legitimate scaling concerns (LRU cache limits, singleflight patterns, HTTP response size bounds), the volume is the highest for any single epic. Items need triage before Epic 9 to prevent silent accumulation.

3. **Case sensitivity bugs (pattern)** — Two instances caught in code review: (a) Story 8.3's `getTodayBriefing` endpoint missing `.toUpperCase()` serialization while `getBriefingById` had it; (b) `test-pipeline.sh` validating lowercase `backfill` instead of API contract `BACKFILL`. Root cause: per-endpoint serialization instead of a shared response transformer.

4. **Previous retro deploy verification still pending** — Epic 7's critical-path items 1-2 (deploy to OpenShift, run test-pipeline on deployed version) have not been confirmed as complete. A18 (version bump + changelog) status also unverified. Two epics of carry-forward on deployment verification.

5. **Orphan files and git governance gaps** — Build artifacts (`tsconfig.tsbuildinfo`) found uncommitted in the repo. `.gitignore` had stale entries. Dev agent does not consistently commit and push after story completion — project lead has been manually prompting git operations.

6. **E2E test fragility** — The test-pipeline has grown to 13 steps depending on Keycloak, LLM providers, OpenShift, and now ARCHITECT user provisioning. When any external dependency degrades, the chain fails. No visual regression testing exists for frontend components.

## Key Insights

1. **Foundation quality compounds across stories within an epic.** The 8→6→3→0 patch trajectory (matching Epic 7's pattern) demonstrates that investing in early story quality reduces defects in later stories. This is now a proven, repeatable pattern across three epics.

2. **Documenting a blocker is not resolving it.** The Keycloak test user gap was documented in four consecutive story completion notes. Documentation creates awareness; only action creates resolution. Cross-story blocker escalation (A20) addresses this.

3. **The final epic must prioritize QA over features.** Eight epics of feature delivery have built a capable system with 735+ tests and zero production incidents. But deferred items, flaky E2E, and missing route-level tests need resolution before the project can be considered production-hardened.

4. **Git governance needs enforcement, not just agreements.** A3 (review-then-close), A4 (git governance per story), and A22 (commit discipline) all exist as agreements, but the project lead still manually prompts commits. Automation (pre-commit hooks, story completion checklist enforcement) is needed.

5. **Multi-model execution is a validated strategy.** Four consecutive epics have successfully used multiple LLM models within the same epic, with the BMAD story format serving as the cross-model handoff contract. This is a mature, proven workflow.
